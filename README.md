# AI-помощник для подготовки товарных описаний

Прототип сервиса для генерации карточек товаров B2B-магазина контрольно-измерительных приборов с использованием LLM.

**Тестовое задание для компании СОЮЗ-ПРИБОР**
**Автор:** Бахимов Олег Николаевич
**Дата:** 13 ноября 2026 г.

---

## Цель проекта

Сервис принимает данные о контрольно-измерительном приборе и генерирует готовую карточку товара:

- SEO-заголовок (до 70 символов)
- SEO-описание (800–1200 символов)
- Структурированный список характеристик
- 3–5 поисковых запросов
- Commercial-блок для менеджера
- Список отсутствующих данных

**Ключевой принцип:** модель НЕ выдумывает характеристики. Все технические значения берутся только из входных данных.

## Быстрый старт

### Требования

- Python 3.11+
- Аккаунт на [RouterAI](https://routerai.ru) (российский AI-роутер, Реестр ПО РФ № 35499)
- ~50 ₽ на балансе для тестов

### Установка

```bash
# 1. Клонировать репозиторий
git clone https://github.com/TomRusski/souz-pribor-ai-assistant.git
cd souz-pribor-ai-assistant

# 2. Создать виртуальное окружение
python -m venv venv

# 3. Активировать
venv\Scripts\activate          # Windows
source venv/bin/activate       # Linux/Mac

# 4. Установить зависимости
pip install -r requirements.txt

# 5. Создать .env из шаблона
cp .env.example .env
# Открыть .env и вставить свой ROUTERAI_API_KEY

# 6. Запустить сервер
python main.py
```

Сервер стартует на ```http://localhost:8000```.  

Проверка работоспособности  
Откройте ```http://localhost:8000/health``` — должен вернуться {"status": "ok"}  
Откройте ```http://localhost:8000/docs``` — Swagger UI с документацией  
Откройте ```http://localhost:8000/debug/model``` — диагностика модели

## Описание промптов

### Структура промптов

#### Используется двухуровневая структура:

1. Системный промпт — задаёт роль контент-менеджера B2B-магазина и жёсткие ограничения.  
2. Пользовательский промпт — шаблон с подстановкой данных конкретного товара.  

#### Ключевые приёмы  

1. Запрет галлюцинаций — явная инструкция «НЕ ВЫДУМЫВАЙ технические характеристики, которых нет во входных данных».  
2. JSON-only ответ — требование вернуть только валидный JSON без markdown-обёрток.  
3. Пометка отсутствий — инструкция использовать «данных нет» вместо выдумывания.  
4. Примеры формата — для каждого выходного поля дан пример ожидаемого формата.  
5. Лимиты длины — контроль объёма для SEO-заголовка (70 симв.) и описания (800–1200 симв.).  

Подробное описание в ```prompts.py```

#### Параметры генерации

| Параметр | Значение | Обоснование |
|:---|:---|:---|
| TEMPERATURE | 0.3 | Минимум креатива = меньше галлюцинаций |
| MAX_TOKENS | 4096 | Достаточно для полного описания |
| max_retries | 3 | Устойчивость к временным сбоям API |

## Принятые решения

### 1. Инфраструктура: RouterAI вместо прямого OpenAI  

* **Решение:** подключение через российский AI-роутер RouterAI.ru
* **Обоснование:**  
* * Оплата в рублях российской картой (удобно для B2B-бухгалтерии)  
* * Серверы в РФ (соответствие 152-ФЗ о персональных данных)  
* * Включён в Реестр ПО РФ N 35499  
* * Автоматическая отказоустойчивость (переключение на резервного провайдера)  
* **Альтернативы:** прямой OpenAI API (проблемы с оплатой из РФ), локальная модель (требует GPU)  

### 2. Фреймворк: FastAPI + Pydantic  

* **Обоснование:**
* * Встроенная валидация входных данных через Pydantic  
* * Автоматическая OpenAPI-документация (Swagger UI)  
* * Асинхронная обработка из коробки  
* * Строгая типизация снижает риск ошибок  
* **Альтернативы:** Flask (меньше встроенных возможностей), Django (избыточен для прототипа)

### 3. Модель: gpt-6.1-terra-pro  

* **Обоснование:**
* * Достаточная длина контекста для полного описания характеристик  
* * Качественная работа с русским языком  
* * Оптимальное соотношение цена/качество для задачи  

### 4. Обработка ошибок: retry с экспоненциальной задержкой  

* **Обоснование:** LLM API иногда возвращают временные ошибки (429, 500)  
* **Реализация:** 3 попытки с задержкой 2, 4, 6 секунд  
* **Критические ошибки** (неверный ключ, отсутствие средств) не повторяются  
* 
Подробно: ```docs/decisions.md```

## Сложности, с которыми столкнулся

1. **YML-фид содержит минимум данных** — только название, артикул и цена. Пришлось парсить страницы товаров сайта для получения полных характеристик.
2. **URL из фида отдают 404** — рабочие ссылки нашёл через поиск по сайту.
3. **Python 3.14 несовместим** — pydantic-core требует компиляции Rust, которая не собиралась на Windows. Решение: переход на Python 3.11 (LTS).
4. **Формат модели в RouterAI** — требует префикс провайдера (openai/gpt-6.1-terra-pro вместо gpt-6.1-terra-pro).
5. **SSL-ошибка при git push** — корпоративный прокси с SSL-инспекцией. Решение: отключение проверки SSL только для домена GitHub.
