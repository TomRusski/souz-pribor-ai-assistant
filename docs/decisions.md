# Принятые решения и ограничения

## 1. Выбор технологий

### 1.1. LLM-провайдер: RouterAI
- **Решение:** подключение через российский AI-роутер RouterAI.ru
- **Обоснование:**
  - Оплата в рублях (удобно для B2B-бухгалтерии)
  - Серверы в РФ (соответствие 152-ФЗ)
  - Реестр ПО РФ № 35499
  - Автоматическая отказоустойчивость
- **Альтернативы:**
  - Прямой OpenAI API (проблемы с оплатой из РФ)
  - Anthropic (отсутствует прямой доступ)
  - Локальная модель (требует GPU)

### 1.2. Модель: gpt-6.1-terra-pro
- **Обоснование:** достаточная длина контекста, качественная работа с русским, поддержка JSON

### 1.3. Фреймворк: FastAPI + Pydantic
- **Обоснование:**
  - Встроенная валидация через Pydantic
  - Автоматическая OpenAPI-документация
  - Асинхронность из коробки
  - Строгая типизация

## 2. Промпт-инжиниринг

### 2.1. Двухуровневая структура
- **Системный промпт:** роль + жёсткие ограничения (запрет галлюцинаций)
- **Пользовательский промпт:** шаблон с подстановкой данных товара

### 2.2. Ключевые приёмы
1. **Запрет выдумывания:** явная инструкция «НЕ ВЫДУМЫВАЙ характеристики»
2. **JSON-only ответ:** без markdown-обёрток
3. **Пометка отсутствий:** «данных нет» вместо выдумки
4. **Примеры формата** для каждого выходного поля
5. **Лимиты длины** для контроля объёма

### 2.3. Параметры
| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| `TEMPERATURE` | 0.3 | Минимум креатива = меньше галлюцинаций |
| `MAX_TOKENS` | 4096 | Достаточно для полного описания |
| `max_retries` | 3 | Устойчивость к сбоям |

## 3. Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Невалидный JSON | 422 + детали поля |
| API-ошибка | 3 попытки с экспоненциальной задержкой |
| Критические ошибки (ключ, баланс) | Без retry, сразу 500 |
| Обрезанный ответ | Логирование `finish_reason=length` |
| Невалидный JSON от LLM | Regex-поиск JSON-блока |

## 4. Безопасность

- `.env` в `.gitignore` — секреты не попадают в Git
- Валидация всех входных данных через Pydantic
- API-ключи только через переменные окружения

## 5. Ограничения прототипа

| Ограничение | Решение в production |
|-------------|---------------------|
| Нет кэширования | Redis с TTL 24 часа |
| Синхронная обработка | Celery + RabbitMQ |
| Нет аутентификации | JWT-токены |
| Нет логирования в БД | PostgreSQL + таблица генераций |
| Нет интеграции с 1С-Битрикс | REST API Битрикса |
| Нет проверки фактов | LLM-as-Judge |
